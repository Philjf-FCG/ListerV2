# Running Lister for several users on the Linux box

One shared server (the same machine that runs Ollama), **one isolated instance per user**.

```
/srv/lister/<name>/              owned by system user lister-<name>, mode 0750 (users can't read each other)
    backend/                     app code, .env (0600), lister.db, OAuth tokens, thumbnails, rotation_backups
    venv/                        that instance's own Python environment
    vinted/listings/...          that user's Vinted data export
    backups/                     nightly database + token backups (14 kept)
/etc/lister/<name>.service.env   the instance's port
systemd:  lister@<name>.service  (runs the app)      lister-backup@<name>.timer  (nightly backup)
```

Each instance has its own database, its own eBay and Google tokens, its own password and its own
port. Ollama is shared and reached on `127.0.0.1:11434`.

| Instance | Port | URL |
|---|---|---|
| first user | 8010 | `http://192.168.1.37:8010` |
| second user | 8011 | `http://192.168.1.37:8011` |

## Security model (please read)

The app holds a user's eBay and Google tokens and can create eBay listings, and the box is reachable
from the whole LAN over plain HTTP. So **every instance requires HTTP Basic credentials** (`ACCESS_USER`
/ `ACCESS_PASSWORD` in its `.env`, generated by `provision-instance.sh`). Never leave the password empty.

- Plain HTTP means the password crosses your LAN unencrypted. That is a reasonable trade on a home
  network you trust; do not expose these ports to the internet (no router port-forwarding).
- Instances run as separate unprivileged users with `systemd` sandboxing, so a bug in one cannot read
  another's files.

## First-time setup (run as root on the server)

Requirements: Python 3.10+ with `venv` (`apt install python3 python3-venv`), `curl`, `systemd`.

```bash
# from this PC (Git Bash), once the repo is on the server or via the commands below
ssh root@192.168.1.37 'mkdir -p /opt/lister/releases'
```

1. **Create each instance** (on the server, from a deployed `deploy/` folder):
   ```bash
   /opt/lister/releases/<rev>/deploy/provision-instance.sh phil   8010
   /opt/lister/releases/<rev>/deploy/provision-instance.sh second 8011
   ```
   This creates the user, directories, port file, `systemd` units and a starter `.env`
   (with a generated password). Re-running it is safe.
2. **Fill in each instance's `.env`** (`/srv/lister/<name>/backend/.env`): the Google OAuth client
   id/secret and the eBay app keys. The same developer apps can serve every user.
3. **Deploy the code** (from this PC, inside the repo):
   ```bash
   deploy/deploy.sh                 # all instances, committed code only
   deploy/deploy.sh root@192.168.1.37 phil   # just one
   ```
4. **Move the first user's existing data** from the Windows PC (run from Git Bash in the repo):
   ```bash
   deploy/migrate-data.sh phil
   ```
   It snapshots `lister.db`, copies the token files, thumbnails, rotation backups and the Vinted
   export, rewrites the `C:\...` photo paths in the database to the server's, and restarts the
   instance. Nothing on the PC is modified. Photos whose path could not be mapped are listed as
   `UNMAPPED`.

## Browser extension (each user)

1. Load the `extension/` folder in Chrome (`chrome://extensions` > Developer mode > Load unpacked),
   or reload it after an update.
2. Right-click the extension > **Options** (or the popup's **Server settings**).
3. Enter **your** address, e.g. `http://192.168.1.37:8010`, username `lister` and **your** password,
   then **Save and test**. Chrome asks permission to contact that server; allow it.

## Signing in to Google Photos and eBay

Google only accepts `localhost` or `https` redirect addresses, so signing in directly on
`http://192.168.1.37:8010` will fail. The redirect URIs therefore stay as
`http://localhost:8010/auth/...` and sign-in is done through a **temporary SSH tunnel**, which makes
the instance appear as `localhost:8010` on the PC doing the sign-in:

```bash
ssh -N -L 8010:127.0.0.1:8010 root@192.168.1.37      # first user's instance
ssh -N -L 8010:127.0.0.1:8011 root@192.168.1.37      # second user's instance (still local port 8010)
```

Then browse to `http://localhost:8010`, use **Connect Google Photos / eBay** as usual, and close the
tunnel. The tokens are saved on the server and refresh themselves, so this is only needed for the
first sign-in and if a token is ever revoked. (If you're moving the first user, the migrated token
files keep them signed in and no sign-in is needed.)

`http://localhost:8010` must be registered as a redirect URI in the Google Cloud console and as the
eBay RuName's *Auth Accepted URL* (it already is, from the single-PC setup). Add each extra Google user
under *OAuth consent screen > Test users* while the app is unpublished.

## Day to day

| Task | Command |
|---|---|
| Deploy new code | `deploy/deploy.sh` (from the repo, after committing) |
| Status / logs | `systemctl status lister@phil` / `journalctl -u lister@phil -f` |
| Restart | `systemctl restart lister@phil` |
| Add a user | `provision-instance.sh <name> <next free port>`, fill `.env`, `deploy.sh`, share the URL/password |
| Show a password | `grep ACCESS_PASSWORD /srv/lister/<name>/backend/.env` |
| Refresh the Vinted export | Download it from Vinted, copy `listings/` into `/srv/lister/<name>/vinted/` (as that user), then `curl -u lister:PASSWORD -X POST http://127.0.0.1:PORT/rotate/import-dates` |
| Run a backup now | `systemctl start lister-backup@phil` |

**Restoring a backup:** stop the instance, copy `backups/<timestamp>/lister.db` over
`backend/lister.db` (and the token files if needed), fix ownership with
`chown lister-<name>: ...`, start the instance.

**Checking Ollama is reachable from the box:** `curl -s http://127.0.0.1:11434/api/tags`.

## Troubleshooting

- **Instance won't start** - `journalctl -u lister@<name> -n 50`. Common causes: a missing `.env`,
  a port already in use, or Python < 3.10.
- **401 in the browser/extension** - wrong password; the extension's test button says so explicitly.
- **Photos are blank after migrating** - run `migrate_paths.py --dry-run` (see its docstring) and look for
  `UNMAPPED` lines; copy the missing photo folders and re-run, it is idempotent.
- **Can't reach the box from another PC** - check the firewall allows the instance's port
  (`ufw allow 8010/tcp` or your distro's equivalent).
- **Running the tests locally** - `cd backend && .venv/Scripts/python -m pytest` and
  `node --test tests/extension/lister-config.test.js`.
